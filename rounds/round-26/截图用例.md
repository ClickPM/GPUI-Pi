### 怎么造出子代理任务

在会话里发一条**显式点名 `Agent` 工具**的指令：

```
用 Agent 工具后台并行派两个子代理：一个找 RPC 协议解析代码，一个找 Job Object 相关代码。
```

**必须点名 `Agent`。** 如果你的 `~/.pi` 下装了别的子代理扩展（例如 `npm:pi-subagents`，
它的工具名是小写的 `subagent`），生产路径会把两套同时加载，模型很可能挑**对方**那套 ——
那样会话里出现的是对方的工作流 ID 与 widget，而本轮的子代理面板**整块不会渲染**，
看起来像功能坏了，实则是没被调用（已记 `rounds/BACKLOG.md` #41）。

模型若仍挑错，可以更硬一点：`不要用 subagent 工具，用 Agent 工具`。
判断是否走对了：会话里应出现名为 **`Agent`** 的工具调用，且 composer 上方出现「子代理 · …」那一行。

关键是要抓到**一个还在跑、一个已完成**的那一刻（用例 1/2 需要）。
如果两个跑得太快都完成了，可以再补派一个长任务制造「运行中」状态。

图片保存到 `.pi/visual-review/round-26/evidence/`（仓库根 gitignored），
或直接回传并告知本地绝对路径。文件名建议 `case-1-panel-collapsed.png` 这样带用例号。

## 用例清单

### 1 · 任务面板 · 折叠态

**位置**：主窗口聊天页，composer 正上方那条横幅区。

**前置状态**：至少 1 个运行中 + 1 个已完成。

**这一行应该长这样**（从左到右）：

```
● 子代理                                    1 运行   ›
↑                                           ↑        ↑
状态点(warning 橙)                    行内汇总    ChevronRight
```

**核对要点**

- 行内汇总**只有一段**，形如 `1 运行` —— **不该**出现 `1 运行 · 1 完成` 这种 `·` 拼接（规范 S-8：`·` 分隔的每段各算一个片段，一行上限 3 段）。
- 行内取值优先级：运行 > 排队 > 失败 > 中止 > 完成。所以有任务在跑时显示的是「N 运行」，而不是完成数。
- 状态点是**橙色（warning）**，因为还有未结算任务。
- 整行文本片段数 = **2**（`子代理` + `1 运行`）；状态点与 chevron 不计入。

### 2 · 任务面板 · 折叠态 · **hover**

**操作**：鼠标悬停在用例 1 那一行上，保持不动再截图。

**核对要点**

- 该行应出现**可见的底色变化**（`muted`，深色下比背景亮一档、浅色下比背景暗一档）。
- 这是本轮修掉的阻断项：上一版写的是「hover 时把文字改成 foreground」，但该行本来就是 foreground，**零像素变化**。所以这张图的唯一目的就是确认「hover 真的有反应」。
- 如果 hover 后**看不出任何差别**，那就是回归了，请直接告诉我。

---

### 3 · 任务面板 · 折叠态 · **tooltip**

**操作**：在用例 1 那一行上悬停约 1 秒等 tooltip 弹出。

**核对要点**

- tooltip 里应显示**完整分桶**，形如 `1 运行 · 1 完成`。
- 这是 S-8 的合规路径：条款明确「被 tooltip 承载的内容不计入片段数」，所以明细放这里而不是行内。
- 只有一个桶时（例如全部完成）行内与 tooltip 内容相同，此时**不会**挂 tooltip —— 那种情况截不到本图，属正常。

---

### 4 · 任务面板 · 展开态

**操作**：点击用例 1 那一行展开。

**这一区应该长这样**：

```
● 子代理                                    1 运行   ⌄
  ● scout      找 RPC 协议解析代码              运行中
  ● scout      找 Job Object 相关代码           12.3s
```

**核对要点**

- 每条任务一行，共 **3 个文本片段**：类型 + 描述 + 一项统计。
- 未结算的任务右侧显示**状态词**（`运行中` / `排队中`）；已结算的显示**一项统计**（优先耗时，没有耗时才退到轮次）—— 同样**不该**出现 `·` 拼接。
- 悬停某一行会弹 tooltip，里面才是完整统计 `5/10 轮 · 12 次工具 · 12.3s · $0.0123`。
- 状态点颜色：运行中=橙、排队中=灰、已完成=绿、失败=红、已停止/达到轮次上限=橙、未知状态=蓝。

---

### 5 · 子代理结果卡片 · 折叠态

**位置**：消息流里，后台子代理完成后出现的卡片。

**这张卡应该长这样**：

```
┌────────────────────────────────────────────────┐
│ ● 子代理 · scout                  已完成    ›  │
│   找 RPC 协议解析代码          a1b2c3d4   12.3s │
└────────────────────────────────────────────────┘
```

**核对要点**

- 卡片边框是**中性弱边框**，不随状态变色（规范 5.2 / 红线 3）——失败的卡片也**不该**是红色描边，红色只出现在左上角那个点上。
- header 行 3 片段：`子代理 · scout`（`·` 分隔算 2 段）+ `已完成`。
- 摘要行 3 片段：描述 + 短 id（8 位）+ 一项统计。
- header 悬停同样应有底色变化（同用例 2）。

---

### 6 · 子代理结果卡片 · 展开态

**操作**：点击用例 5 的卡片 header 展开。

**展开区应该长这样**：

```
│ ● 子代理 · scout                  已完成    ⌄  │
│   找 RPC 协议解析代码          a1b2c3d4   12.3s │
│   │ 结束原因：…（仅 watchdog 停止时才有）      │
│   │ worktree：…（仅跨仓任务才有）              │
│   │ transcript：/tmp/pi-agent-outputs/….log    │
│   │ <子代理产出的正文，Markdown 渲染>          │
```

**核对要点**

- 展开区是**左竖线 + 缩进**，**不是**再套一张卡片（规范 5.3 / 红线 2）。
- 展开区整体是 **12px 弱色**文字，**不应**比摘要行更大更黑 —— 本轮修过这条（此前它继承消息容器的 14px 主文本色）。
- `transcript：` 那行**默认不会出现**：内核的 `output_transcript` 开关默认关闭。想让它出现需要在 `~/.pi/agent/subagents-lite.json` 里设 `agent.outputTranscript: true` 再重跑。**不出现是正常的**，不必强求。

### 7 · 窄窗口 900×700 · 面板展开态

**操作**：把窗口缩到约 900×700，保持面板展开。

**核对要点**

- 描述文字应**截断（省略号）**，而不是把右侧统计挤出可视区。
- 类型名也有宽度上限，长类型名同样截断。
- **composer 必须仍然完整可见** —— 展开区有 160px 高度上限，不该把输入框顶出窗口。
- 任务多于 7 条左右时，展开区内应出现**滚动条**（本轮修过：此前是裸滚动，没有任何「还有内容」的线索）。

### 8 · 无子代理会话（回归）

**操作**：打开一个从未派发过子代理的会话。

**核对要点**

- 这条是回归验证：面板在无任务时整块不渲染，不留空隙。
